# Credit Card Default Predictor

A logistic regression model that estimates the probability a credit card
holder defaults on their loan, with a decision threshold chosen by the
actual cost of getting it wrong — not just accuracy.

`train.py` reproduces the model end-to-end &nbsp;|&nbsp; `app.py` is the
inference UI

---

## Business framing

In credit risk, the two ways a model can be wrong are not equally expensive:

- **False negative** (model says "will repay," borrower actually defaults):
  the bank loses the outstanding loan principal, minus whatever is
  recovered — typically the most expensive outcome in the portfolio.
- **False positive** (model says "will default," borrower would actually
  have repaid): the bank forgoes the interest margin on that one loan, or
  the customer has to go through manual review. Annoying, but cheap by
  comparison.

Because a missed defaulter costs several times more than a wrongly-declined
good customer, optimizing for raw accuracy is the wrong objective — a
model can post 95% accuracy while still missing 1 in 5 actual defaulters,
which is exactly what happens here at the default 0.5 cutoff (see below).

This project tunes the decision threshold under an explicit **5:1 cost
ratio (FN:FP)**, which is a reasonable starting assumption for unsecured
consumer credit and is easy to re-tune if your loss data says otherwise —
the threshold sweep in `train.py` accepts any ratio.

## Metrics

Model: Logistic Regression · Features: `Income`, `Age`, `Loan`,
`Loan-to-Income` · Test set: 600 held-out samples (81 actual defaults)

**AUC-ROC: 0.983** — the model separates defaulters from non-defaulters
well across all thresholds; the real question is *where* to draw the line.

| Threshold | Precision (default) | Recall (default) | F1 | Read |
|---|---|---|---|---|
| 0.50 (default cutoff) | 0.83 | 0.79 | 0.81 | balanced, but misses 21% of defaulters |
| **0.18 (cost-tuned, 5:1)** | **0.67** | **0.94** | **0.78** | catches 94% of defaulters at the cost of more manual reviews |

Confusion matrix at the cost-tuned threshold (600 test samples):

|  | Predicted: No Default | Predicted: Default |
|---|---|---|
| **Actual: No Default** | 482 | 37 |
| **Actual: Default** | 5 | 76 |

At this operating point the model misses only 5 of 81 actual defaulters,
down from 17 at the default threshold — at the cost of 37 vs. 13 false
alarms. Under a 5:1 cost ratio that trade is worth it; the exact threshold
is a business input, not a fixed model property.

## Feature rationale

The dataset provides four fields: `Income`, `Age`, `Loan`, and
`Loan-to-Income`. The last is a pre-computed ratio (loan size relative to
income) rather than something engineered in this project, but it's worth
noting *why* it matters: absolute loan size and absolute income are each
weak signals on their own (a $10K loan is trivial for a high earner and
risky for a low earner), but their ratio directly represents leverage —
how much of a borrower's income is on the line — which is a standard risk
signal in consumer credit. The model's own coefficients on the test data
back this up: `Loan-to-Income` has by far the largest positive weight of
the four features, followed by `Age` with a negative weight (older
borrowers in this dataset default less).

**Known limitation:** this is a small, synthetic dataset (2,000 rows, 4
columns) rather than the larger UCI/Kaggle "default of credit card
clients" dataset with payment history and bill statements. It's enough to
demonstrate the full pipeline — training, evaluation, threshold tuning,
deployment — but a production version would need richer behavioral
features (payment history, utilization trends, delinquency counts) rather
than four static fields.

## Deployment

`app.py` is a Streamlit dashboard with two tabs: a **Predict** tab that
takes borrower inputs and returns a default probability plus a
threshold-adjustable decision, and a **Metrics** tab showing the test-set
precision/recall/AUC at both the default and cost-tuned thresholds.

Run locally:
```bash
pip install -r requirements.txt
python train.py      # trains the model, saves model.pkl + metrics.json
streamlit run app.py
```

Deploy free on [Streamlit Community Cloud](https://share.streamlit.io):
point it at this repo and `app.py` — `requirements.txt` is picked up
automatically.
